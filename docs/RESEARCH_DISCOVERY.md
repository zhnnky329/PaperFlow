# Research Discovery 实施设计

日期：2026-10-20。范围是现有 PaperFlow 的 arXiv 发现与 DeepSeek 内容筛选；CVF、机器人会议/期刊独立来源列为后续扩展。

## 现有架构与复用

已检查 `backend/app/{arxiv,metadata,db,main,worker,storage,html}.py`、Alembic、前端路由、API 客户端、样式及测试。数据库模型集中在 db.py；main.py 通过单实例数据目录锁保护本地服务，元信息用单线程池，Marker 有独立持久队列，Finder 有独立对账线程。前端是 React Router + App.tsx 工作台，既有 Settings、Button、主题 token 可复用。

复用 arxiv.parse/request 的 ID、官方域名、重定向、限速与流大小限制；复用 metadata.normalize_doi；推荐导入调用与现有 arXiv 导入相同的服务函数，沿用元信息后台队列。Discover 不调用 Marker、不保存候选 PDF、不改变阅读器。网络/AI 使用独立线程，数据库事务只涵盖短暂写入。

## 数据流与持久化

自动/手动检查 → 单一发现任务 → 分类 feed（cs.CV/cs.RO/cs.AI）按更新时间分页 → ID/DOI 与发现池和 Library 去重 → 保守初筛/优先级排序 → 限量正文提取 → 预算预留 → DeepSeek JSON → 验证结果/缓存 → Discover → 用户主动加入 Library。

增量迁移 0004 只创建 discovery_papers、discovery_runs，不修改原论文、分类、标签与进度表。发现条目保存规范 ID、版本、元数据哈希、分析及分析哈希、依据、反馈、Library 外键与时间；运行表保存状态、阶段、计数、预算、错误和分页进度。原 Library 删除只清除外键。初次观察最近七天；分页未完成保持旧水位并持久化 offset，下次继续，不能因为达到上限就跳过未处理论文。旧论文新版由 lastUpdatedDate 排序识别，不用提交日期过滤。上游分页非快照，时间重叠及 ID 去重缓解更新漂移。

## AI 与成本

初筛只拒绝明确排除项；关键词与自然语言用于排序，没有关键词命中仍可交给 AI。方向描述、关键词、优先级共同进入提示。AI 输出 recommend/skip、0–100 相关性、既有方向 ID、简短理由和约 100–200 字中文总结；分数是模型的相关性判断，不代表客观质量。

官方 HTML 纯文本优先；受限 PDF 提取作为回退；完整正文、部分正文和摘要明确区分。长文有界压缩并标为部分正文。模型、提示版本、论文内容决定缓存；兴趣调整不自动重算，用户可明确重新分析。未配置密钥仍可抓取/筛选；AI 默认关闭，用户启用才允许网络调用。

每次最多分析 10 篇，默认 50,000 token 预算；调用前使用保守字节估算预留并提交，成功记录供应商实际用量。超时/崩溃等不确定费用保留预留，失败不自动重付，用户可重试。密钥来自服务端环境或 data dir 下权限 0600 的独立文件，写入即清空前端输入、不回传、不入公开 settings/日志/常规备份。

## 页面衔接

侧栏仅增加 Discover 入口及新增数量；独立 /discover 主体以单列阅读效率为先。筛选推荐、最近新增、历史、感兴趣/稍后、忽略，按方向/分数/时间排序，提供原文、加入文献库、反馈、显式重新分析。无 AI 结果显示候选状态。Settings 只追加配置区域，延续系统字体、现有浅深色 token 和控件；不重做原导航/Library/阅读器。

## 分期与验收

1. 发现：真实公开 arXiv feed、增量/分页、去重、调度并发、迁移保留原数据。
2. AI：官方 API 核实、正文/摘要回退、严格解析、预算、缓存、脱敏；收费真实推理需用户自行验收。
3. 页面：列表/筛选/反馈/入库/设置，浅深色和空/失败态，浏览器集成。
4. 回归：孤儿任务恢复、失败重试、备份、pytest、lint/typecheck/Vitest/Playwright。

成功标准：自动与手动检查不会并发；重启保留推荐与反馈；同一未变论文不会重复分析；只有主动入库增加 Paper；已有 Library 和阅读状态在升级及回归测试后保持。真实 feed/正文请求与隔离测试分开记录，模拟 AI 响应仅验证协议，不能冒充真实推荐。
