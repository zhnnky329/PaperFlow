# PRD — PaperFlow V1 产品需求

## 0. 概要

- **产品**：PaperFlow，个人、本地运行的科研论文收藏、管理与阅读器。
- **主要用户**：单个科研/工科大学生；中英文论文，尤其是机器人、运动规划、SLAM/VLN、机器学习等 PDF/LaTeX 论文。
- **系统**：macOS Apple Silicon 为主要运行环境；Chrome/Chromium 打开 localhost Web App。
- **成功标准**：用户可以在一次会话中“添加论文→自动识别来源→打开合适的阅读版本→双语阅读→关闭并恢复进度”，不需要手动复制转换产物或反复管理 PDF 文件夹。

## 1. 核心原则

1. Local-first。元数据、用户笔记（如果后续实现）、阅读状态、已导入 PDF 和生成 HTML 存在本机。
2. 优先高质量阅读体验而非 Zotero 功能广度。
3. 官方 HTML（若提供）优先用于网页阅读，但不把远端 URL 伪装成本地离线 HTML。
4. Marker 失败不妨碍读 PDF；元数据失败不妨碍收藏；网络失败不妨碍读已有本地论文。
5. 默认复用 Read Frog + 用户自行配置的 DeepSeek，不擅自调用付费 API。
6. 不做开发者演示品：所有 V1 行为必须有真实后端/持久化/错误处理。

## 2. MVP/V1 规范及优先级

### P0 — V1 必须完成

**P0-1：添加论文**
- 拖放、文件选择导入单个/多个 PDF；校验真实 PDF 类型（文件头、解析尝试）、最大文件大小可配置，超限提示。
- 粘贴 arXiv URL/ID（`abs`、`pdf`、`html`，可带 `vN`）导入；识别标准 arXiv ID 和版本，规整 URL，服务器端拉取元数据。元数据拉取失败仍可建立待补全条目。
- 对原生本地 PDF，先提取 PDF 元数据或文件名作为备选；允许手工编辑标题、作者、年份、摘要/链接字段。
- 由 SHA-256 文件哈希避免相同 PDF 重复导入；arXiv 使用规范化 ID + 版本策略处理重复。重复时引导“打开已有条目/关联新文件”，不暗中覆盖。
- arXiv URL 导入默认保存链接/元数据，PDF 可以按需下载缓存；若用户从本地上传 PDF，则始终复制入应用数据目录，不依赖导入位置长期存在。

**P0-2：管理 Library**
- 所有论文列表、标题/作者/年份、来源、当前首选阅读格式、最新阅读时间、转换状态。
- 搜索标题/作者/arXiv ID/标签（至少子串匹配，必要时 SQLite FTS5）；排序：最近添加、最近阅读、年份、标题。
- 多个 Collection / Tag；论文可属于多个 Collection、拥有多个 Tag。
- 状态：`unread`（未读）、`reading`（阅读中）、`finished`（已读），可手工切换。
- 删除须二次确认，说明数据库条目和本地文件的删除范围；避免误删库外路径。
- 重启不丢元数据、分类和状态。

**P0-3：阅读**
- PDF 阅读：PDF.js（或官方 pdfjs-dist）真正加载并阅读后端授权的 PDF；翻页、缩放、页码导航、适配宽度；错误展示与重试。
- HTML 阅读：能显示 Marker 输出的标题、正文、层级标题、图片、表格、公式及参考文献。提供目录跳转、段落宽度控制、字体大小、亮/暗主题。
- 官方 arXiv HTML：打开经过验证的官方 HTML 链接，默认新标签页（避免 iframe/跨域限制）；保留从 Library 返回的明确路径。不能假定能自动读取外部页的阅读进度。
- 内部 Marker HTML 必须通过 `http://127.0.0.1/...` 提供，不能靠 `file://`；验证 Chrome Read Frog 扩展在实际页面上的翻译行为。
- 记录 PDF 最后页码与缩放、内部 HTML 最后章节锚点和滚动比例，打开时恢复。外部 HTML 的进度只能手动标记/不追踪，UI 如实提示。
- 支持浏览器后退/前进；键盘快捷键至少 `/` 搜索、`Esc` 返回/关闭弹层（输入中避免冲突）。

**P0-4：转换**
- 对无官方 HTML 的本地 PDF 支持一键“Convert to HTML”；可在 Settings 设置 `auto_convert_on_import`（默认关闭，以免耗费资源）。
- 使用 Marker 官方工具/受控 adapter，运行在独立进程；不要在 HTTP 请求线程内执行模型推理。
- 状态机 `not_started → queued → running → succeeded / failed / canceled`；显示错误原因和重试；重启时重置/恢复孤儿任务状态。
- 文件输出采用 staging temp dir → 校验 HTML + 资源完整性 → 原子提升；失败不能覆盖先前可用的 HTML。
- 默认每次仅跑 **1 个**转换任务，避免占满 MacBook Air 内存；转换结果与 Marker 参数/版本、原 PDF 哈希关联以便复用/重新转换。
- 转换中 PDF 阅读完全可用，前端不用等转换完成才能操作其他页面。

**P0-5：翻译可用**
- V1 默认方案：用户安装 Chrome Read Frog，自己在扩展中配置 DeepSeek API；本应用在 HTML 阅读页提供清晰的翻译入口/帮助，不保存或获取 Read Frog API Key。
- 通过端到端人工测试：至少一篇含公式与图片的 Marker 论文，Read Frog 能选择段落和正常双语翻译；标题、公式、脚注及表格不能出现灾难性错位。
- 如果 Read Frog 无法稳定处理 PaperFlow 的 HTML：**V1 发布前必须实现最小原生 DeepSeek 翻译适配器**（参见 `ARCHITECTURE.md`），不能仅写“以后会支持”。替代方案包括关闭不兼容装饰、调整静态 DOM，优先解决兼容性而不是立即自研。
- 翻译属于主动操作，有网络和潜在 Token 成本；在外部 Read Frog 模式由浏览器插件管理；不谎称 PaperFlow 已持久化译文。

**P0-6：可靠性**
- 默认仅绑定 loopback；无法访问模型/远端 API 时应用照常启动。
- 应用重新启动后 PDF、HTML、数据库数据保留；异常退出后能检测孤儿转换作业。
- 错误提示必须面向用户可理解，详细 traceback 写入日志（不能包含密钥）。
- 可备份和恢复 data dir；升级数据库使用迁移，不在应用启动时删除既有数据。

### P1 — 达到稳定 V1 后可做

- PDF 页内文本搜索/高亮；HTML 正文全文索引（SQLite FTS5）。
- 批量标签/批量修改状态；单篇简短 Markdown 笔记。
- 最近阅读、收藏、阅读时间统计。
- 键盘快捷键设置、导出简单 BibTeX。
- arXiv 官方 HTML 的本地快照（需要独立处理 URL/脚本/样式和资源依赖）。

### 明确不做（V1 Out of Scope）

- 多人账号、云同步、多人协作、移动客户端、浏览器扩展开发。
- Zotero 同步、引用样式管理、复杂 BibTeX/CSL、批量 DOI 抓取、文献关系图谱。
- OCR 引擎自研、PDF 像素级转换、任意网站全能抓取。
- 强制基于 LLM 的论文问答/RAG、向量数据库。
- 自动批量请求 DeepSeek 翻译所有论文（费用不可控）。

## 3. 用户故事与正常操作流

**S1：从 arXiv 收集论文**
1. 点击 `Add Paper`，粘贴 `https://arxiv.org/abs/xxxx.xxxxx`。
2. 页面创建草稿条目并异步拉取标题、作者、发布日期和 arXiv 页面链接。
3. 服务端验证 `https://arxiv.org/html/<id>` 是否真的可访问且返回 HTML。若可用，首选 `Official HTML`；若不可用，显示 `PDF` 与 `Download PDF / Convert`。
4. 阅读官网 HTML（新标签页，Read Frog 在官网使用）；Library 中保留链接与状态。

**S2：导入只有 PDF 的论文**
1. 拖入 PDF，出现导入完成提示；直接可读原 PDF。
2. 点击 `Convert to HTML`，看到 queued/running；此时仍可阅读 PDF。
3. 转换成功后打开 PaperFlow 内部 HTML；浏览器 Read Frog 可直接翻译。
4. 再次打开同篇论文跳过转换，恢复阅读位置。

**S3：网络或推理失败**
1. arXiv 请求失败/HTTP 429：允许收藏草稿并提供 `Retry metadata`。
2. Marker 下载模型失败/内存不足/超时：任务 failed，可查看安全裁剪的错误信息并重试。
3. HTML 结构较差：允许立即切回原始 PDF，而不丢数据。

## 4. 数据所有权与路径行为

- PDF 文件导入：复制到 PaperFlow 数据目录；不改动用户原文件。
- arXiv 仅链接导入：应清楚标识 `Remote only`；下载后标识 `Cached PDF`。
- 删除数据库条目：可选择将该论文归属的本地文件移至 Trash（V1 可简化为明确确认后删除，但须保证仅在 PaperFlow data dir 内）。
- HTML 缓存与 PDF 是独立资产；重建 HTML 不影响原 PDF。
- 暂不保证外部浏览器页面的自动阅读进度和离线能力。

## 5. 错误处理与可访问性

- 所有异步操作具有 loading/success/error/empty 视图；失败可重试；不弹出重复 toast 风暴。
- 对网络错误、资源缺失、模型不可用、PDF 已损坏分别给予动作建议。
- 键盘可操作核心导航，焦点可见；对比度满足 WCAG AA 的通常要求；暗色模式文字清晰。

## 6. V1 发布阻断条件

- 无法导入并持久化 PDF / arXiv 条目。
- Marker 跑通但 HTML 公式/图片资源大面积丢失且无 PDF 降级。
- PDF 页面打不开，或转换失败使 PDF 页面也打不开。
- Read Frog 在 Marker HTML 上不可用且无合格原生翻译替代。
- 进度和分类在重启后丢失。
- 任意输入可以造成路径穿越、在 HTML 中执行恶意脚本、泄露本地任意文件。
- 依赖需要用户在非开发模式下手动改源码/复制产物才能使用。

## 7. V1 不等于绝对完美

复杂表格和数学公式的转换结果可能不完美，因此必须能在 PDF 原文中对照。性能指标采取可重复实测，不在没有测试数据时硬性承诺“数秒转换”。按 `TEST_PLAN.md` 记录平台、内存、Marker 模式和测试结果。
